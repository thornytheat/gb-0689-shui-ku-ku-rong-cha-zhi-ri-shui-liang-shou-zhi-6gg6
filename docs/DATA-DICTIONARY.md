# 水位与水量定义

id、station为字符串。time含时区，统一UTC，日账在+08:00午夜拆分。level单位m；inflow/outflow单位m3/s或L/s，归一m³/s；空值不等于零。负流量与曲线外水位隔离。
curve为[[水位,库容],...]，水位及库容必须严格递增，库容非负，单位m与m³。只对范围内水位分段线性插值，端点允许。
同站同刻按version最高记录采信，同版不同值全部隔离。重复旧版有独立证据。输入=采信+隔离；原始行号保留。
相邻观测间以梯形积分计算流量体积，超过max_gap_hours则不插补。日界处先线性插出流量与水位，再分别积分及按曲线换算库容。日账是已覆盖时段的收支，覆盖不足24h始终待补测。
日收支差=库容变化-入库+出库，绝对值超过tolerance_m3需复核。缺测优先于超差。无蒸发降雨模型，差额不自动认作漏损。
数值为Decimal字符串，日切与整段积分容许1e-9m³以内十进制除法尾数。规则参数和输入摘要参与幂等ID；批次原子保存，复核版本冲突返回409。

原始到达序小于此前最大事件时刻的测次标记arrival=迟到，仍保留并按事件时间排序积分，迟到不会推进水位回退。

## 库容曲线改版（curve_switch）

参数 `curve_switch={'effective_at': ISO8601含偏移, 'curve': [[水位,库容],...]}` 为可选项；缺省时全部沿用 `params.curve`，字段与计算结果与旧版完全一致。新曲线同样要求至少两点、水位库容严格递增、库容非负。

- 生效时刻 T（统一UTC）之前用旧曲线，T 起（含 T 点）用新曲线。M4 每条测次按观测时刻选曲线并标注 `curve_basis=旧曲线/新曲线`。
- T 点对同一水位同时算新旧库容，差额计入当日 `curve_adjust`（曲线调整量），在日账中单列；它不是入库也不是出库，不进入 `storage_change`，也不进入 `residual=storage_change-in_m3+out_m3`。
- 跨 T 的观测段在 T 处再切一刀：物理库变 = 旧曲线段变化 + 新曲线段变化；T 点调整每站只登记一次，重跑同一改版不得重复调整。T 恰与观测点或日界重合时同样登记一次。
- 日账 `segments` 记录前后分段：T、T点水位、旧库容、新库容、调整量；`curve_basis` 标注该日列示依据。
- 任一站在 T 点缺少覆盖（T 落在缺测缺口或观测范围外）即判 `CURVE_SWITCH` 切换失败：管线整体抛错，不保存批次、不写改版登记，旧版日账原样保留。
- 改版在 M2 曲线校核页登记（`POST/GET /api/m2/revisions`，SQLite `curve_revisions` 表，按生效时刻幂等）；生效时刻所在 +08 日若已复核确认，返回 `SWITCH_CONFLICT` 且不试算。
- 复核“通过”的完整24h日写入 `confirmed_days`（快照含当时曲线依据）。之后重跑时这些日整行替换为确认快照、保持原曲线，其余日按现行曲线续跑，结果附 `confirmed_days` 与 `resume_from`；复核“退回”删除对应确认。
- 改版参数与规则版本参与幂等ID；不做蒸发降雨、地下渗漏与外部调度，曲线调整不得被归入这些项。
